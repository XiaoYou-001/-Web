# 智绘旅游

Vue 3 + Vite 旅游应用，包含线路规划、景点与酒店浏览、票务演示、AI 客服和 Go WebSocket 聊天服务。

使用 Docker Compose 构建、启动和验收完整服务，请参见[部署手册](deploy/README.md)。

## 启动

使用 Node.js 22.12 或更高版本，在项目根目录执行：

```powershell
npm ci
npm run dev
```

AI 后端通过 `npm run start:backend` 启动，密钥和配置参见 [后端指南](NODEJS_BACKEND_GUIDE.md)。Go 聊天服务在 `go-chat-server` 目录通过 `go run .` 启动。

## 接口与错误处理

前端 HTTP 请求统一通过 `apiClient`，AI 请求由 `aiService` 调用。默认基地址为 `/api`，开发时 Vite 转发至 Node 服务，生产部署需配置 `/api` 反向代理，或构建前设置公开变量 `VITE_API_BASE_URL`。普通请求默认 10 秒超时，AI 默认 45 秒，可分别通过 `VITE_API_REQUEST_TIMEOUT_MS`、`VITE_AI_REQUEST_TIMEOUT_MS` 调整。

请求会区分取消、超时、网络故障、限流、权限错误、服务未配置及响应格式错误。临时故障可手动重试，不自动重发请求。停止等待、切换客服/模型、刷新对话或离开页面会取消旧请求并清理定时器，过期响应不写入当前会话。

线路当前仍保存在本地账号数据中。保留的线路 HTTP 适配器只有在显式配置 `VITE_ROUTES_API_BASE_URL` 后才启用，未配置时明确报“尚未接入”，接口失败也不会悄悄返回模拟推荐。接口路径与 HTTP 方法见[线路适配器](src/services/routeService.js)。适配器不再读取旧版 `authToken`；本地演示账号不能作为真实后端登录凭证。

## 本地账号与个人数据

当前账号属于本地演示，仅保存在此浏览器中，请勿使用真实密码；尚未接入真实后端认证、支付或短信发送。微信入口也为需要主动确认的演示流程，详见 [微信说明](WECHAT_INTEGRATION_GUIDE.md) 和 [手机号验证说明](SMS_INTEGRATION_GUIDE.md)。

线路、每日行程、景点收藏、酒店收藏和价格订阅按账号 ID 保存。刷新或重新登录后恢复同一账号的数据，切换账号时清空当前展示，再读取新账号的数据。个人中心的收藏数量包含景点、酒店及已收藏线路。

- 新账号的“我的线路”为实际空列表；推荐线路仍作为可选的演示内容。
- 价格订阅只保存订阅信息，实际价格监控与短信、微信推送尚未接入。
- 保存失败时保留编辑草稿，不显示成功，也不提前更新收藏或订阅状态。
- 同一账号在其他标签页修改的数据会通过浏览器存储事件刷新；当前存储不提供跨设备同步或数据库级并发事务。

个人业务数据使用 `travel_data:v1:<账号ID>` 键，包含版本、所属账号、线路、收藏、订阅和行程。读取时校验版本和结构，数据损坏或版本不兼容时保留原始值并显示错误，不自动覆盖。

旧版未记录所属账号的 `price_subscriptions` 和 `user_itineraries` 原样保留，不自动归给任何账号，也不自动删除。旧版仅保存在页面内存中的线路、收藏在刷新后无法恢复。

## 聊天室

聊天服务与前端需要使用同一版协议。连接携带账号 ID 和房间 ID，服务端按连接所属房间广播，并按房间内不同账号统计在线人数；多个标签页使用同一账号计为一人。同行旅行房间的身份由 Node 服务签发的令牌决定；普通固定房间仍使用本地演示账号的查询参数，尚无服务端登录凭证校验。

每条消息带独立 ID，前端收到服务器回显后确认服务器已接收。10 秒未确认或连接断开时标记为“未确认送达”，可手动重发；同一 ID 在服务端最近 2048 条消息缓存中只广播一次，重发仅返回原消息回执。缓存淘汰或服务器重启后不保证去重，回显也不代表其他用户已经阅读。

断线使用有上限的指数退避重连，心跳无响应会主动重建连接，离开房间时释放监听器和定时器。聊天记录按账号、房间保存在浏览器，最多保留最近 100 条。配置 `CHAT_HISTORY_DIR` 后，Go 服务另按房间持久化最近 500 条消息；首次进入或断线重连时，前端通过 `/history` 拉取服务端历史，首次加载最近一页，重连时按最后一条已确认消息 id 增量补收，与本机记录去重合并后显示提示。浏览器进入离线状态会立即断开并停止重试，恢复在线后自动重连，并以最多 3 次自动重发未确认消息。服务端不主动推送离线消息，超出 500 条的历史无法补回；损坏的本地记录会保留，用户主动清除后才恢复写入。

默认连接当前站点的 `/ws`，HTTPS 页面自动使用 `wss`。开发环境由 Vite 转发至 `127.0.0.1:8080`；生产环境需要将 `/ws` 反向代理至 Go 服务并开启 WebSocket 升级，或构建前设置 `VITE_CHAT_WS_URL` 为可访问的 WebSocket 地址。

普通固定房间在配置聊天签名后仍保持无令牌连接，以兼容现有聊天入口；同行旅行房间（`trip-<旅行ID>`）必须携带服务端签发的短期令牌。Go 服务同时校验 WebSocket 来源：默认允许无 Origin 请求、同源与本机地址；配置 `CHAT_ALLOWED_ORIGINS`（完整 `scheme://host[:port]`，逗号分隔）后只接受白名单内的来源。`/history` 支持 `afterId` 增量游标，并只对已知来源返回 CORS；开发环境由 Vite 将 `/history` 代理到 Go 服务，也可用 `VITE_CHAT_HTTP_URL` 指定独立地址。

## 同行协商空间与旅行聊天室

旅行工作台底部的「同行协商」先要求绑定服务端账号：使用个人中心已绑定的手机号和 6–20 位密码登录，账号不存在时自动注册。绑定成功后，服务端为当前浏览器签发会话令牌，按本地账号分别保存；退出协作身份不会删除本地旅行数据。服务端所有成员、投票、留言、任务与聊天室权限判断都基于该令牌对应的账号，不接受客户端传入的账号 ID。

- 组织者创建协作空间后可生成一次性邀请码（默认 7 天有效，可取消）；成员凭码加入。角色分为组织者、成员与只读访客。
- 成员默认可以投票、留言和认领任务，但不能修改共享旅行资料（标题与候选池）；组织者可逐个授予「允许编辑共享资料」。只读访客不能投票、留言、认领任务或进入同行聊天室。
- 组织者和获准编辑的成员可在各自工作台修改每日行程，再点「同步本地行程到云端」。已有同步记录时，不同活动的改动会自动合并。同一活动的独立字段也会合并。双方修改同一字段且值不同时，页面列出差异，由提交者逐项选择后再同步。成员可用「把云端行程写回本机」保存共享安排。每份行程最多 31 天，每天最多 30 项活动。
- 候选地点投票按账号幂等，支持改投与撤回。任务同一时间只能被一人认领。行程标题与候选池更新受版本号保护。
- 移除成员会清理其投票和全部未使用邀请码；退出空间需重新获得邀请码。轮询每 20 秒刷新一次协商内容，页面隐藏或断网时暂停。
- 服务端数据默认写入 `logs/runtime/collaboration`，可用 `COLLAB_DATA_DIR` 指定；账号与旅行文件均为 JSON，并发写入采用临时文件替换。

旅行聊天室由 Node 服务用 `CHAT_AUTH_SECRET` 签发 15 分钟令牌，Go 服务用同一密钥校验；客户端在令牌过期前刷新，并校验令牌中的房间与账号。`CHAT_ADMIN_SECRET`（至少 16 字节）配置后，Node 在移除成员或成员退出时尽力调用 Go 的 `/internal/revoke`：立即断开在线连接，并把该账号在该行程房间列入 16 分钟黑名单（覆盖旧令牌剩余寿命），握手、历史读取和重连都会被拒绝；账号重新加入协作空间时自动解除黑名单。调用失败不会阻止移除，此时旧令牌在 15 分钟过期前仍可能通过校验。未配置两个密钥时，同行聊天入口显示未配置，普通聊天室仍可使用。

当前限制：跨设备同步与冲突处理已由真实 HTTP 服务测试和 Go 测试覆盖，聊天消息互通与成员移除后即时断开已用两个独立浏览器（同机）实测，但尚未在真实双设备中人工验收；协商内容依赖轮询而非推送，成员通过手动同步提交每日行程，编辑中的草稿留在本机；聊天室已支持离线/重连后的历史补收与未确认消息自动重发，但没有服务端离线推送，且每房间只保留最近 500 条，超出部分无法补回；黑名单保存在 Go 进程内存，服务重启后清空（旧令牌仍受 15 分钟有效期约束）；Go 服务固定监听 `:8080`，生产环境需自行反向代理并显式配置聊天密钥与来源白名单。

## 表单与操作反馈

登录和注册复用账号服务的手机号、密码基础校验规则。提交时同时显示各字段错误，并将焦点移到第一个错误输入；修改字段后清除对应旧错误，保存失败时保留草稿。手机号提交前修剪首尾空格，密码不做修剪。账号或存储错误持续显示在表单内，成功提示可跨页面显示。

全站通用操作提示通过 `useFeedback` 和 `FeedbackHost` 展示，业务页不再直接调用浏览器 `alert/confirm`。同类重复提示合并，最多显示三条；成功、信息和注意提示 5 秒后关闭，错误提示由用户关闭。AI 对话和地图等已有的局部错误继续在原位置展示。

删除线路、取消订阅、清空聊天记录和切换账号等动作使用原生 `dialog` 确认框，默认聚焦取消按钮，支持 Tab 焦点约束和 Escape 取消。同一时间只处理一个确认；关闭或离开所属页面、切换账号会取消等待中的确认，异步恢复后还会检查账号或聊天室是否仍匹配。提示组件卸载时清理计时器和待处理动作。

预订、支付等未接入真实服务的入口明确说明演示状态，不报告真实业务成功；点击演示支付不再把订单直接标为已支付。个人中心的订单详情、订单评价（仅对已完成订单），以及线路的本地分享（复制/导出计划文本）已在前端完成并持久化到本账号；接入真实支付后这些流程再切换到真实订单系统。酒店评价只保存在当前页面，景点复制信息只在剪贴板写入成功后提示成功，拒绝权限或取消分享都有对应处理。

## 旅行备份、规划检查与预约日历

- 在旅行详情的「旅行备份」下载当前编辑的 JSON 文件。在另一浏览器登录后，从「我的旅行 → 从备份恢复」查看名称、日期和条目数，确认后会创建一条可独立编辑的新旅行。备份保留活动、预约锁定、地点、准备清单、费用和账本。手账与照片由手账页面单独管理，账号及分享管理凭据保存在原浏览器。
- 展开「规划检查」，点击具体问题即可跳到对应日期并聚焦输入框，包括活动时间、停留分钟和费用记录。修正后问题数随即更新。
- 在「行程日历」可将锁定预约导出为 `.ics` 文件。按预约的当地时间选择目的地时区和提前提醒，在日历应用打开文件并确认导入。默认提醒为提前 30 分钟，已跳过的预约会略过。

## 手机今日行程与离线阅读

日期处于旅行期间且旅行状态为「已准备」时，详情首屏展示当前活动、下一站和当天下一项固定预约。根据上一站到预约地点的交通分钟数显示最晚出发时间，点地点可打开导航。未填写停留时长时，已开始的最近一站显示「结束待确认」。已过时的未勾选活动可在「待补记」确认完成或跳过。行程有时区时按目的地时间判断，否则使用设备时间。

联网时，在工作台点「保存到此设备」，等待离线资源准备完成。在同一浏览器保持该账号登录，断网后重开旅行详情可查看已保存的日程、地址和预约备注。离线阅读器需要 HTTPS 或 localhost；页面分别显示行程保存时间和离线资源准备时间。

## 同行共享账本

在「同行协商」连接或加入空间后，展开「同行共享账本」。组织者和普通成员可以登记自己垫付的支出并勾选分摊成员，只读访客可以查看。金额按分均摊，有余数时按成员加入顺序分配。支出记录可展开核对每人的份额，按人汇总显示已付、分摊、应收和应付。

已打开账本时断网，登记的支出会先保存在本机的待同步列表。联网后或再次打开同一账号的协作空间时会重试，也可以手动重试。同一笔支出在服务端使用同一请求编号去重，待同步金额在获得服务端确认后计入共享总额。旅行原有的个人账本独立保存。

## 当天行程延误

在「日程编辑」或「出行模式」中，为有预约的活动勾选「锁定开始时间」。当前活动晚结束时，点「延误调整」输入分钟数。预览会结合停留和到下一站的交通时间，显示后续活动的新时间，以及预约前一站最晚何时出发。耗时缺失时会提示估算依据。确认后可在旅行工作台点「撤销修改」恢复。

## 景点地图与页面清理

地图使用高德 Web 端（JS API）Key。在根目录 `.env` 配置 `VITE_AMAP_KEY` 与服务端 `AMAP_SECURITY_JS_CODE`，将 `VITE_AMAP_SERVICE_HOST` 设为 `/_AMapService`。Node 后端已实现固定上游的安全代理；Vite 开发时同源转发，生产部署需将此路径转发给 Node。安全密钥不能带 `VITE_` 前缀，不能发给浏览器。可选 `VITE_AMAP_SDK_PROXY=/_AMapService/sdk` 通过同源加载 SDK；`AMAP_WEB_SERVICE_KEY` 对当前 JS API 查询不必填写。修改配置后重启前后端。详见[高德安全代理说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

脚本加载会合并并发请求，成功后复用 SDK。超时或失败可在页面内重试；离开地图或页面时取消当前加载、移除本次失败或取消的脚本和回调，并解绑标记及地图事件、销毁地图实例。其他调用仍在等待时保留共享加载，不删除第三方脚本。SDK 加载和地图渲染各有 10 秒超时，不再依赖固定延时等待 DOM。

已经移除示意坐标。景点地图页支持真实 POI 搜索，用户明确选择同名候选后可加入旅行。工作台可逐项确认地点并查询步行、驾车交通耗时，记录地点 ID、GCJ-02 坐标、距离、来源与查询时间。修改地点、调换顺序或删除下一站会使旧估算失效。出行模式为已确认坐标提供[高德步行导航](https://lbs.amap.com/api/uri-api/guide/travel/route)。地点尚未确认时可按名称搜索。手机、慢网和省流模式下，景点地图先显示地点列表，可直接加入旅行，也可手动展开底图。

2026-10-30 本机内置浏览器实测：故宫博物院及景山公园的 POI 查询成功；两地步行返回20分钟/1445米，驾车返回22分钟/2563米。这些仅为验收时结果，不作为固定交通数据。底图在该浏览器仍出现渲染超时，尚未完成真实底图视觉验收；页面保留失败提示、重试与外部地点链接。`tests/browser/map-services.html` 是仅供 Vite 开发环境使用的公开地点联调页面，不进入生产构建。

票务页的演示搜索会使用点击时提交的条件，再次搜索会取消同类旧任务；重置或离开页面会取消待执行任务，避免旧结果回写。`test:map` 使用模拟 SDK、脚本和计时器验证加载合并、取消、重试和卸载清理，无需真实地图 Key；真实高德鉴权、底图与外网连接需在配置后另外联调。

### 只读分享服务

已实现 `/share/:id` 免登录查看页及 `/api/travel-shares` 创建、读取、更新和撤销接口。默认关闭；在服务端 `.env` 配置 `TRAVEL_SHARES_DIR=.travel-shares` 后启动 Node 后端即可启用。此目录应为独立持久化目录，不能放进静态资源服务或提交到版本库。公网跨设备访问还需要部署前端和后端、配置同源 `/api` 代理及 HTTPS；本机 localhost 链接不能供其他设备直接访问。

每条链接有独立的管理凭据，用于更新或撤销。客户端在请求前保存管理凭据，服务端只保存其散列；本地演示账号 ID不能用于授权撤销。凭据按浏览器账号与旅行保存，清除浏览器数据将丢失该链接的管理凭据。分享有效期7天，公开字段仅有名称、日期、活动名称和时间；备注、预算、费用、预订信息在客户端与服务端均被排除。持有链接的人都可以读取。发布者可在工作台预览公开字段的变化，再确认更新原链接。收件人刷新即可查看新版本及更新时间，到期日沿用首次发布时间计算。

存储适用于单个 Node 进程，使用文件原子替换。单目录最多1000条快照、撤销与过期记录；每IP每小时最多创建20次、撤销60次，限流为进程内状态。撤销与过期记录会保留以拒绝迟到的创建请求（过期清理只移除公开内容，保留不可复用标记），不能随意清除后复用旧链接。大规模或多实例部署需迁移数据库、共享限流与正式账号认证。分享 GET 返回 `no-store`；撤销不能删除对方已保存的副本。

现已覆盖持久化重读、敏感字段剔除、错误撤销凭据、过期、服务未配置和先撤销后迟到创建等接口测试。尚未做公网部署与跨设备浏览器验收。
